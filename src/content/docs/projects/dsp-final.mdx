The FFT found the pitch 2.68 times faster than autocorrelation, and it kept tracking about 200 Hz higher in the test sweep. Either method works for a simple auto-tune. For the EENG 411 final project, I built the real-time MATLAB pipeline that runs both detectors and measured the results. Jonas Krider and I wrote the detector code on this page together.

An FFT finds the pitch by looking for the strongest frequency bin. Autocorrelation (ACF) looks for the lag where a signal best matches itself.

## The signal chain

The pipeline is two files. `Main.m` runs the test or live input, and `Run.m` does the calculation once per frame: filtering, decimation, both detectors, and the timing. The code isn't public because it was course or sponsor work.

Audio comes in at 48 kHz and goes through a cascaded Butterworth band-pass filter that keeps the vocal range. Decimation keeps every Nth sample, and two stages, by 3 and then by 2, bring the rate down to 8 kHz.

### FFT detector

The FFT reads the current frame, 682 samples after decimation. It applies a Hamming window and zero-pads the frame to an 8192-point FFT, then fits a parabola through the peak and its neighbors to resolve pitch between bins:

```matlab title="Run.m"
spectraPitch = fft(pitchSignal_NoDc .* hamming(L_pitch), nfft_hires);
[~, I] = max(abs(spectraPitch(1:floor(end/2)))); % Max amplitude bin

left_bin  = abs(spectraPitch(I-1));
max_bin   = abs(spectraPitch(I));
right_bin = abs(spectraPitch(I+1));

p = 0.5 * (left_bin - right_bin) / (left_bin - 2*max_bin + right_bin);
f0_fft = (I - 1 + p) * (Fs_pitch / nfft_hires);
```

### Autocorrelation detector

The ACF reads a longer 2048-sample history. It limits its lags to 55 to 2000 Hz and takes the first local maximum, as long as it clears a 0.2 threshold:

```matlab title="Run.m"
minLag = floor(Fs_pitch / 2000);
maxLag = floor(Fs_pitch / 55);
searchIndices = (centerIdx + minLag) : min(centerIdx + maxLag, length(acor));

% Autocorrelate search indexes sample segments
segment = acor(searchIndices);

% local peaks
[peaks, locs] = findpeaks(segment);
```

### Retuning

The retuning stage picks the nearest note in 12-tone equal temperament, the standard Western scale. An exponential moving average with $\alpha = 0.2$ smooths the target, so it jumps between notes less often. The stage then resamples the frame by the pitch ratio, applies a Hann window, and normalizes it.

## Latency

On paper the FFT is $O(n \log n)$ and the ACF is $O(n^2)$. I timed each detector with `tic` and `toc` around its own block on every frame. The FFT was faster and more consistent:

| Per frame | FFT | ACF |
| --- | --- | --- |
| Mean | 0.22 ms | 0.59 ms |
| Standard deviation | 0.26 ms | 0.74 ms |
| Maximum | 1.18 ms | 3.21 ms |

The report's table labels the second row variance, but `latencyplots.m` computes it with `std`, so it is a standard deviation in milliseconds.

## Where each one fails

We swept a chirp, a tone that rises in frequency, from 50 Hz toward 4 kHz. Both methods track the pitch inside the pass band. The ACF fails past the 1500 Hz pass-band edge, near 1600 Hz. The FFT keeps tracking into the transition band and collapses near 1800 Hz, before the 2000 Hz stop band.

### The lag grid

The report puts both failures down to the filter. Running the detectors on a steady tone shows the ACF has a second limit of its own. At 8 kHz a 1700 Hz tone has a period of only 4.7 samples, so the lag grid is coarse and the error grows. The search also starts at lag 4, and a peak needs a neighbor on each side. Once the period drops below about 4.5 samples, the first peak is lost and the search takes the second one, at twice the lag:

$$
f_{est} = \frac{f_s}{2 \cdot f_s / f} = \frac{f}{2}
$$

Set the tone to 1800 Hz in Figure 4 and the ACF reports about 900 Hz. The filter has cut that tone by 48 dB, but it is still above the noise, so the lag grid is what fails. The FFT has no such limit. It holds until the tone drops under the noise, near 1935 Hz.

### Retuning across the sweep

Retuning follows the tracker. It maps correctly up to about 1800 Hz and fails in the filter's attenuation zone. The report rounds that failure point to 2 kHz. Around frame 1300 it works again, because a second chirp falling from 4 kHz enters the range the tracker can detect.

## Which method to use

The report found both methods accurate within about the same margins for a simple filter. The FFT has lower latency. The report also credits the ACF with better tracking against error and lower space complexity. The tracker cannot read below 55 Hz, the lower bound set in the code. The report names octave errors and a tremolo from overlapping frames as the next problems to fix.
