You write your resume in one JSON file, and the script lays it out on one page by the rules on [eeprep's resume page](https://eeprep.com/advice/resume/).

## How it fits one page

The script runs LuaLaTeX and reads the page measurements back from its log.

1. It starts at 11 pt text with 0.5 in margins. It steps the text down to 10 pt, then the margins down to 0.4 in, and keeps the first layout that fits.
2. It grows line spacing and the section and entry gaps together until the page is full. Spacing never shrinks below its compact values.
3. If nothing fits at the tightest layout, it stops and says about how many lines to cut.

```python title="build.py"
def fit(typeface):
    """Find the roomiest layout that fits on one page, then fill the page.

    Returns (font, margin, fill, free lines), or None and the log of the
    tightest try when nothing fits.
    """
    for font, margin in LAYOUTS:
        pages, log = compile_once(typeface, font, margin)
        if pages == 1:
            return (font, margin, *fill_page(typeface, font, margin, log)), log
    return None, log
```

Spacing never moves a line break, so page height grows in a straight line with spacing. Filling the page then takes two builds: one at the roomiest spacing to find the slope, and one at the spacing that exactly fills the page.

## How it checks the result

Applicant tracking systems read a PDF's text layer. So each build extracts the text with `pdftotext` and confirms that every heading, entry, and bullet comes out whole and in reading order. It also notes bullets with a short last line and pages with more than 3 empty lines.

The fonts ship with the project, so the PDF looks the same on every system. CI builds every example and fails if a PDF is not exactly one page.

The [resume on this site](/resume/viewer/) uses a JavaScript port of the same steps.
